Prompt Control Block PCB Architecture

The deterministic kernel of the Resume Intelligence Engine. Splits static operating laws from dynamic applicant evidence for prefix cache saturation, zero token drift, and dual-model dispatch.

Operating System Analogy

Process Control Block (PCB)

Just as an OS maintains an immutable control block defining process context and capabilities, RIE locks the model into an invariant Recruiter-First operating identity that never mutates across runs.

Prefix Cache Saturation

Static System Prefix = Free Compute

The 9,400-character SYSTEM message is strictly static. DeepSeek and OpenRouter cache the prefix, yielding 80–90% cost discounts and eliminating prompt re-computation latency.

Dual-Model Specialization

Right Engine for the Right Slot

LaTeX resume compilation demands zero hallucination and strict grammar (DeepSeek Flash 1017); Cover Letter writing demands rhythm burstiness and human cadence (GPT-6 Luna).

SYSTEM MESSAGE (PCB)

The Invariant Operating Kernel

Identical across all runs for a document type. Eligible for Prefix Cache hit.
9,400 chars

1. Recruiter Mental Model Contract Static

Codifies the 5-second human scan: (1) Does Title match? (2) Is there measurable impact? (3) Is it clean? Reframes ATS as a passive database, not a scoring evaluator.

"ATS software is a parser and routing database, not a human reviewer. Make the document easy for both: standard headings, plain text, simple one-column structure."

2. The 6 Invariant Resume Laws Static

Hard behavioral constraints: LAW 1 Title Lock; LAW 2 Impact Over Tasks; LAW 3 Clarity Over Density; LAW 4 Story Over Lists; LAW 5 One-Page Budget; LAW 6 Natural Keywords.

LAW 2 — IMPACT OVER TASKS: NEVER write "worked on" or "assisted". ALWAYS write: [Strong verb] + [Specific what] + [Result that mattered].

3. Anti-AI Writing Fingerprint Rules Static

Distilled from MIT-licensed detection research: sentence rhythm spread floor (≥20 words), mid-band cap (<50%), zero em dashes (---), and zero parallel negation ("Not X, but Y").

"Zero em dashes (---). Do not use an em dash anywhere in the letter. Overuse is the single strongest AI writing marker."

4. LaTeX Preamble & Package Banning Static

Hard blacklists for XeLaTeX/LuaLaTeX packages (fontspec, polyglossia) and commands (\vspace, \newpage) preventing compiler crashes on standard TeX Live distributions.

BANNED packages: fontspec, xunicode, xltxtra, unicode-math, polyglossia BANNED commands: \setmainfont, \setsansfont, \newpage, \vspace{}
USER MESSAGE (PAYLOAD)

The Dynamic Runtime Turn

Mutates on every run. Minified JSON and job-specific parameters.
Variable

1. Minified SELECTED_DATA_POOL Dynamic

Pruned subset of candidate profile. Experiences, projects, and certifications selected by local deterministic algorithm. Whitespace-stripped JSON.

{"selected": {"experience": [{"key": "iiser_research_internship", ...}], "projects": [{"key": "neuronest", ...}]}}

2. RESUME_SELECTION Traceability Dynamic

Selection report containing scoring rationale, target budget counts, and user priority markers (primary, secondary, keyword_dependent).

{"schema_version": "resume-selection-2", "page_budget": {"target_pages": 1, "max_experience_entries": 2, "max_project_entries": 3}}

3. Candidate MOTIVATION_DATA Dynamic

Personal origin story, authentic seed sentences, and target role adaptations. Gives the cover letter model the applicant's genuine midnight voice.

{"origin_stories": ["Altum project management..."], "seed_sentences": ["I've spent 2 years obsessing over..."]}

4. Raw JOB_DESCRIPTION & Output Contract Dynamic

Target job posting plus the strict output contract mandating zero conversational preamble: OUTPUT FINAL LATEX ONLY. No explanation.

OUTPUT FINAL LATEX ONLY. No explanation. No thinking out loud. SELECTED_DATA_POOL: ... JOB_DESCRIPTION: Software Engineer building Python...

Parallel Dispatch Implementation (rie/generate_pipeline.py)

Both generators execute in parallel workers. Total generation time is max(t_cv, t_cl) rather than t_cv + t_cl, halving user wait time.

with ThreadPoolExecutor(max_workers=2) as executor: cv_future = executor.submit(cv_runner, config, data_pool, jd) cl_future = executor.submit(cl_runner, cl_config, data_pool, motivation_data, jd) cv_result = cv_future.result() cl_result = cl_future.result()
